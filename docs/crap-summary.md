# CRAP refactoring summary

Baseline and after reports are generated by `tools/crap.py`; full rankings are
in [`crap-baseline.md`](crap-baseline.md) and [`crap-report.md`](crap-report.md).

## Result

| Metric | Baseline | After |
| --- | ---: | ---: |
| Functions analysed | 380 | 372 |
| CRAP > 30 | 22 | 6 |
| CRAP > 100 | 7 | 3 |

## Changes

- Split `BindingWizard::handle_param_key` into range and choice handlers, with
  a shared `navigate_list` helper for modal lists.
- Split `param_items` into layer, HID-usage, and constant builders.
- Added direct unit tests for modal parameter ranges, layer/constant/HID
  parameters, layer rename/navigation, layout selection, and list helpers.
- Added tests for generic/custom binding labels, unknown behaviors, and all
  eight modifier key symbols.
- Added connect-screen keyboard/mouse tests and a mouse layer-row test.
- Split `App::handle` into connection/edit/layer message handlers.
- Split `apply_action` into layer, layout and save/quit helpers.
- Split `handle_editor_key` into navigation and command handlers.
- Split `LayerModal::handle_key` into rename and list handlers.
- Added device-event, lock-poll, connect-list scroll, mouse-wheel navigation,
  editor-command and quit/unlock action tests.

The removed hotspots were `handle_param_key` (CRAP 204.98 → below the report
cutoff), `generic_label` (132.00 → covered), and `param_items`
(75.92 → refactored/covered). The gate-driven split also removed `handle`,
`apply_action`, `handle_editor_key` and `LayerModal::handle_key` from the
high-CRAP set.

## Latest review pass

A correctness review pass then split the three remaining core hot spots
(`handle_edit_message`, `handle_layer_message` and the simulator's
`handle_keymap`) into per-message/per-request helpers, and added regression
tests for the review's fixes: firmware-faithful parameter validation, layer-name
length limits, physical-layout refresh after discard, snapshot retry/staleness,
narrow-terminal rendering and grid-based navigation. Line coverage is now
**82.37%** with **0** excluded-set functions above CRAP 30.

All three remaining whole-project CRAP > 100 rows are hardware/terminal glue
(`establish_session`, `spawn_reader`, `spawn_input_thread`) and remain excluded
from the gate, as do the rest of the transport and entry-point modules.

## Remaining high-CRAP functions

The remaining top entries are deliberately not “fixed” by weakening tests:

- `transport::ble::connect/scan/adapter/send` — CoreBluetooth/FFI; needs
  hardware integration tests, not pure unit tests.
- `transport::serial::spawn_reader`, `tui::mod::spawn_input_thread` — OS threads
  and terminal I/O.
- `main::list_devices`, `tui::mod::run/run_loop` — entry points and hardware
  discovery.
- `tui::render` helpers and exact-CRAP-30 connection helpers — UI/connection
  code covered by TestBackend and manual checks, not a practical unit target.
- `tui::app` dispatch functions were split under gate pressure and now fall
  below the CRAP 30 threshold; their integration/Gherkin coverage is retained.

## Gate policy

The gate excludes `src/transport/**`, `src/main.rs` and `src/tui/mod.rs` (FFI,
OS threads and entry points), then enforces:

- **CRAP > 30: 0**
- **CRAP > 100: 0**
- **line coverage: ≥ 79%**

The excluded functions are still listed in the full report, but they are not
practical unit-test targets. After the gate-driven refactor the core set has no
function above CRAP 30. The remaining core zeros are the hardware-spawning
`connect_choice`/`connect_by_bluetooth_name` helpers (CRAP 30) plus a set of
low-CRAP accessor/rendering helpers; the report labels the former as glue and
the latter as unclassified unit-test gaps.

The report generator also excludes `#[cfg(test)]` modules and
`src/verification.rs` (Kani-only code), so test helpers and formal harnesses do
not appear as bogus 0% runtime functions.

## Reproduce

```bash
cargo llvm-cov --all-targets --json --output-path /tmp/coverage.json
PYTHONPATH=/tmp/zmk-py python3 tools/crap.py /tmp/coverage.json \
  --top 30 --output docs/crap-report.md
```

`tools/crap.py` requires `lizard` (`python3 -m pip install lizard`). Coverage is
LLVM region coverage excluding each function's entry region; complexity is
lizard's cyclomatic complexity. CRAP is therefore an approximation used for
prioritisation, not an absolute quality score.
